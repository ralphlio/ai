01 / MENTAL MODEL

先建立总认知：
模型只是发动机，产品是整辆车

把 GPT-5-Codex 或 Claude Opus 这类大模型想成一台发动机：它只会做一件事——给定一段文字（上下文），预测下一段文字。它不能读你的文件、不能跑命令、不记得上一句话。模型自身甚至不知道该"什么时候停"。

Codex、Claude Code 这类产品真正的主角，是发动机外面那套底盘 + 车身——工程上叫 harness（承载框架）：负责把请求拼装成提示词、调用模型、执行模型点名的工具、把结果喂回去、管理权限和记忆、决定何时收尾。

OpenAI 工程团队的一个共识被广泛引用："模型是一个组件，Agent 才是一个系统；大部分工程量在系统这一侧。" 类比互联网产品：选模型 ≈ 选底层算法（约占 20% 工作量），围绕算法做的编排、存储、权限、分发、体验层才是产品真正的护城河（80%）。

02 / THE ENGINE

核心引擎：Agent Loop
—— 从"一问一答"到"干完一件事"

Chatbot 的交互是对讲机：发一句、回一句，结束。Agent 的交互是一个员工干活的全过程：接需求 → 查资料 → 动手 → 看结果 → 调整 → 交付。这个"接→查→做→看→再决策"的循环，就是 Agent Loop，Codex 和 Claude Code 的机制几乎一模一样。

  1. 01 组装提示词 — 把你的请求 + 系统指令 + 工具清单 + 项目规范 + 环境信息拼成一个大 prompt
  2. 02 模型决策 — 模型输出两种东西之一：给用户的话，或工具调用请求（"帮我跑 npm test 并告诉我结果"）
  3. 03 框架执行工具 — harness 真正去读文件/改代码/执行命令，把输出追加回上下文
  4. 04 循环 — 回到 02，一圈叫一个 turn，直到模型不再调工具、产出最终答复

官方例子：一句"修复 auth 模块的 bug"，可能触发 4 个 turn 几十个动作——先跑测试看挂在哪、读两个文件、改代码、重跑测试、修 lint、再跑测试，最后提交。整个过程中人只说了一次话。

PM 视角：模型的"智商"决定单步决策质量，但体验上限由 loop 的工程决定——失败重试、并行执行、超预算熔断（Claude SDK 里的 max_turns / max_budget_usd 就是我们的"防跑飞"配置）。

03 / CONTEXT ENGINEERING

上下文工程：Agent 时代的内存管理

模型没有工作记忆，一切靠"上下文窗口"这块有限的内存。Codex 每次请求发送的 prompt 是一个严格分层的栈（层与层带 role 优先级）：

① System 系统指令 — 服务器控制
② 工具定义（每个工具的 schema）
③ Developer 指令 + AGENTS.md / CLAUDE.md — 项目规范、测试命令，放在仓库里
④ 沙箱权限规则 + 环境信息（cwd、shell）
⑤ 用户消息 + 全部历史 turn — 客户端控制，越滚越大

PM 类比：这就像我们给外包同学发的《协作说明书》。AGENTS.md / CLAUDE.md 是"写在代码库里的 PRD"——项目约定、怎么跑测试都写清楚，Agent 表现显著更好。它也是用户可感知的"配置项"。

PROBLEM · 历史重发的代价

第 N 个 turn 要重发前 N-1 个 turn 的全部数据 → 传输量随对话长度近似平方级增长。OpenAI 故意不用服务端会话存储来省事：保持每个请求自包含、无状态，才能满足"零数据保留（ZDR）"客户。这是典型的 toB 合规换性能的架构取舍。

MITIGATION ① · PROMPT CACHING 前缀缓存

新内容永远追加在末尾，旧 prompt 是新 prompt 的精确前缀 → 模型计算可复用，传输平方级、计算近似线性。但缓存很脆：中途换模型、换工具、改沙箱配置都会击穿缓存——Codex 接入 MCP 时曾因工具列表顺序不稳定，意外把缓存命中全部打没。

MITIGATION ② · COMPACTION 上下文压缩

快撑爆时，框架把老历史替换成一份"代表性摘要"（Codex 用携带模型潜状态的加密载荷，Claude SDK 自动 compaction 并发 compact_boundary 事件）。效果 ≈ 会议纪取代录全文：越久远的记忆越模糊。所以官方最佳实践是——换新任务就开新会话；长期规则写进 CLAUDE.md/AGENTS.md（每次都会重新注入），别留在聊天里。

04 / HANDS & GUARDRAILS

手脚与安全带：工具、沙箱、权限谱系

HANDS · 工具集

两家几乎同构的文件系统 + shell：
Read / Edit / Write · Glob / Grep · Bash · WebSearch / WebFetch
再加编排类：Agent（派生子 Agent）、Skill、AskUserQuestion。外部系统通过 MCP（数据库、浏览器、内部 API）接入。
调度细节：只读工具并行跑；改状态的工具（Edit/Bash）串行跑防写坏——和我们对"并发读写锁"的直觉一致。

SANDBOX · 爆炸半径控制

Agent 会执行任意命令，必须假设它可能"手滑"。Codex 本地跑在 OS 级沙箱（macOS Seatbelt / Linux bubblewrap，2026 年补上了 Windows 专用沙箱），云端任务则每个任务一个预装仓库的隔离容器；默认断网、写文件限制在工作目录。Claude Code 用权限系统 + Hooks 做同等约束，Web 版跑在 Anthropic 托管的云沙箱。

APPROVAL · 人机协作开关

Codex 的协议是双向的：服务端可以反向请求客户端——"我要执行这条命令，允许吗？"，用户不回，turn 就挂起等待。Claude 用 permission mode 谱系 + PreToolUse hook（相当于我们后台的策略网关/审批流，在工具执行前拦截、校验、直接否决）。

05 / DISTRIBUTION

多端架构：一套内核，处处运行

Codex 最早只是个 CLI。然后团队被要求：VS Code 要、网页版要、macOS App 要、JetBrains / Xcode 也要——为每个入口重写 Agent 逻辑是不可能的任务。这与互联网公司的经典困境同构：一套核心业务如何分发到 App / H5 / 小程序 / 开放平台。

第一次尝试：MCP，失败了

先按行业标准 MCP（Model Context Protocol，Anthropic 2024-11 发布、OpenAI 等迅速跟进的"工具接入 USB-C"）把 Codex 暴露成 MCP server。结果发现：流式进度、中途暂停求批准、结构化 diff 这些真实 Agent 交互语义，MCP 当时根本承载不了。（注意：MCP 没死——它成了"工具/数据源接入"的标准；只是不适合做"整个 Agent 的远程协议"。）

第二次尝试：自研 App Server 协议

OpenAI 把 Agent 内核（loop、线程管理、工具执行、配置、鉴权）收进 Codex core，外面包一层 JSON-RPC 双向协议（App Server），任何客户端通过 stdio 就能驱动完整 Agent。协议向后兼容，所以 Xcode 能锁定旧客户端、持续对接新服务端——生态伙伴的发布节奏与 OpenAI 解耦。

架构教训（原话）：正确的抽象往往不存在，直到你试过错误的那个。 而且这条演化路径不是设计出来的，是被需求逼出来的。

对照：Anthropic 的开放策略

Claude Code 走了同一终点的另一条路：先做 CLI 爆款（2025-02 预览、05 GA），再把同一套 loop 封装成 Claude Agent SDK（TS/Python，内嵌完整运行时），让开发者把"Claude Code 的能力"嵌进自家产品；配 MCP + Skills + Subagents 做扩展生态，Web/桌面端补齐触点。
策略差异：OpenAI 自研协议保体验闭环，Anthropic 立开放标准换生态位——一个像自建物流，一个像开放平台。

云端形态 = 无头 CMS

Codex Web 版：worker 拉起云容器 → 检出仓库 → 启动同一个 App Server 二进制 → 事件流推给浏览器。关掉标签页任务照跑，因为状态在服务端。"本地/远程同构"让同一产品既能在你的机器上动手，也能在云上 7×24 干活。

06 / EVOLUTION

演进路线：从"补全一行"到"委托一周"

回看 2021→2026，这条路线不是功能堆叠，而是「能力跨过阈值 → 架构允许委托 → 成本降到可卖」三条线的交汇。每个阶段都解决上一阶段的"不可能"。

2021.08 → 2023.03 · 阶段 0：单次生成

初代 Codex：会"接话"的代码模型

基于 GPT-3 微调的 Codex 驱动了 GitHub Copilot——补全一行、补全一个函数。没有循环、没有工具、没有记忆。API 于 2023 年初关闭，"Codex"暂时只是一个代号。同期：AutoGPT/BabyAGI 证明了"给 LLM 挂循环"的雏形可行，但模型太笨，演示大于实用。

2023 → 2024 · 阶段 1：接口标准化

Function Calling、Computer Use、MCP

2023-06 OpenAI 把"模型点名副程序"做成正式 API（function calling），工具调用从 prompt 技巧变成产品接口；2024-05/07 Claude 推出 Artifacts 与计算机操作（Computer Use）beta——模型开始能看屏幕、点鼠标；2024-10 Anthropic 首个 Agent SDK；2024-11-25 MCP 发布，“给模型接万物”有了统一总线，次年获全行业跟进。地基完工。

2025 H1 · 阶段 2：AGENT 产品化元年

Claude Code 与 CODEX 双双落地

2025-02 Claude Code 以终端研究预览版发布（Opus 4 前后正式 GA 5 月）；2025-04 OpenAI 开源 Codex CLI，05-16 发布云端 Agent Codex（codex-1，为工程微调的 o3）：CLI + 云沙箱 + ChatGPT 里派任务。"结对编程"第一次变成"异步派活"。7 月 Operator 并入 ChatGPT Agent，通用操作型 Agent 试水。

2025 H2 → 2026 · 阶段 3：长任务 · 生态位 · 多智能体

为"委托"重构产品形态

2025-09 GPT-5-Codex 把 Agent 收回 ChatGPT 主线；2025-10 Claude 侧发布 Agent Skills（可安装的"做事方法论"）与 Claude Code on the web；2025-11 Opus 4.5 主打"可连续自主工作数小时"、能力曲线首次冲破 80%；随后 Agent Teams（多智能体协作）、Codex App Server 全端统一、Windows 沙箱（2026-06）、GPT-5.2-Codex 接连落地。竞争焦点从"谁更聪明"转向"谁更能被放心地委托"。

演化驱动力 ①

可靠性阈值

单次成功率 30%→70%，意味着"人审核一次"变成"人抽查十次"——委托形态（PR、异步任务）才开始有商业意义。

演化驱动力 ②

Harness 工业化

缓存、压缩、沙箱、权限、双向协议……每一步都在"更少的监督"下"更长的自主时长"，二者互为因果。

演化驱动力 ③

经济学

token 降价 + 缓存摊薄重复成本 + "effort 分档"（不同难度用不同推理预算），把一个任务的边际成本打到用户可以按"任务包月"付费。

08 / WHAT'S NEXT & SO WHAT

下一阶段演进的赌注，
和一个 PM 的行动清单

赛道上下一步 · 四个公开押注

① 时长竞赛：从小时到"一周"

模型可自主工作时长约每 7 个月翻倍（业界常用度量）。产品含义：交互从"实时监督 session"变成"任务收件箱 + 异常升级"，接近项目管理工具。

② 记忆与个性化：跨会话身份

压缩丢信息 → 需要持久记忆层（用户偏好、项目图谱）。谁掌握"可迁移的工作记忆"，谁就有迁移成本护城河。

③ 组织形态：多智能体团队

Subagents/Agent Teams = 给"虚拟公司"做组织架构设计：谁规划、谁执行、谁验收、成本预算如何分摊到"部门"。

④ 信任基建：验证、审计、定价

自动化测试/评审 = SLA 的底座；日志与 Hook 审计 = 合规；计费从 token（资源）走向按任务/成果（outcome-based pricing）。

PM 行动清单 · 明天就能用

  1. 01 像写 PRD 一样写 AGENTS.md / CLAUDE.md。项目规范、验收标准、命令清单入仓 → 直接兑换成 Agent 表现，成本几乎为零。
  2. 02 需求按 turn 粒度拆分。"每圈有明确下一步"的任务 loop 效率最高；开放式指令（"优化下代码库"）是烧钱黑洞。
  3. 03 给 Agent 上预算三件套：max turns / 成本上限 / 超时降级。没有熔断的自动化不是提效，是裸奔。
  4. 04 子 Agent = 并行外包小组。把脏活（大范围检索、日志分析）隔离给 subagent，主上下文只收摘要——控制"内存"占用与成本的正规打法。
  5. 05 指标换代：从"回答质量"转向任务完成率、人工干预率、单任务成本、自主时长。这是 Agent 时代的 DAU/GMV 等价物。
  6. 06 评估自动化测试/评审基建。委托规模的上限 = 你能多便宜地验证结果。CI 覆盖率低，Agent 就只能停留在"副驾驶"。
  7. 07 权限设计按谱系做（plan→审批→自动→绕过），把"信任等级"做成可升级的产品机制，而不是一键开关。

终局判断：模型会持续变快变便宜，而"被信任地委托"这门生意，赢在 harness、生态与信任积累——就像云计算赢在控制台、计费与合规，而不是赢在机柜。
